# دليل مصوّر بالنقرات: تدريب Lion-1 على Colab من الصفر

> **أولاً وأخيراً — أزل هذا الالتباس: لا يوجد ملف LoRA ترفعه.**
> ملف LoRA هو **ناتج** العملية، يصنعه Colab بنفسه في الخطوة ٥، ثم يدمجه في الخطوة ٦ ويحوّله
> إلى GGUF في الخطوة ٨. الشيء الوحيد الذي «ترفعه» هو **الدفتر** (`Lion1_LoRA_Colab.ipynb`).

| ما ترفعه أنت | ما يصنعه Colab تلقائياً |
|---|---|
| الدفتر `.ipynb` (ملف نصي صغير) | البيانات ← LoRA ← النموذج المدمج ← `lion-1-Q4_K_M.gguf` |

---

## ٠) ما تحتاجه قبل البدء

| المتطلب | التفاصيل |
|---|---|
| حساب Google | مجاني — هو نفسه حساب Gmail |
| GPU مجاني | T4 من Colab (لا تحتاج بطاقة، ولا دفع) |
| الوقت | ساعة إلى ساعتين أول مرة |
| الجهاز | يعمل من الهاتف أو الحاسوب. **من الحاسوب أسهل بكثير**؛ من الهاتف افتح Chrome وفعّل «موقع الكمبيوتر» |
| المستودع | يجب أن يكون **عاماً** (public). إن كان خاصاً: اعمل Fork عاماً أو ضع توكن GitHub في الخلية ١ |

---

## ١) نزّل الدفتر إلى جهازك

1. افتح: `https://github.com/starmaen/LionAI`
2. اضغط الزر الأخضر **`Code`** ← **`Download ZIP`**.
3. افتح ملف ZIP (من تطبيق الملفات) ← ادخل `LionAI-main/model/` ← ستجد **`Lion1_LoRA_Colab.ipynb`**.
4. احتفظ بهذا الملف — هو الذي سترفعه في الخطوة ٣.

> بديل أسرع من الحاسوب: افتح رابط الملف مباشرة ← زر **`Download raw file`**.

---

## ٢) افتح Colab وفعّل GPU **قبل** أي شيء

1. اذهب إلى: **https://colab.research.google.com**
2. سجّل الدخول بحساب Google.
3. من القائمة العلوية: **`Runtime`** ← **`Change runtime type`**.
4. في **`Hardware accelerator`** اختر **`T4 GPU`** ← **`Save`**.
5. تحقق: في الشريط العلوي تظهر كلمة **`T4`** بجانب `RAM/Disk`.

> إن لم تجد T4: جرّب لاحقاً (الطلب كبير أحياناً)، أو استخدم **Kaggle** بنفس الدفتر.
> بدون GPU سيستغرق التدريب ساعات بدل ساعة، وقد يفشل.

---

## ٣) ارفع الدفتر إلى Colab

1. في صفحة Colab: **`File`** ← **`Upload notebook`**.
2. تبويب **`Upload`** ← **`Choose File`** ← اختر `Lion1_LoRA_Colab.ipynb` من الخطوة ١.
3. سيُفتح الدفتر وفيه ١٢ خلية مرقّمة بالعربية: ١ ← ٩.

---

## ٤) شغّل الخلايا بالترتيب (زر ▶️ على يسار كل خلية)

> لا تشغّل «Run all» أول مرة: راقب كل خلية. بعد أن تنجح مرة، استخدم `Runtime → Run all`.

### الخلية ١ — جلب الكود
- ماذا تفعل: تنزّل المستودع من GitHub إلى Colab وتدخل مجلد `model/`.
- المتوقع: سطر فيه `git clone …` ثم قائمة ملفات (`README_AR.md`, `train_lora.py`, …).
- إن ظهر `تعذّر جلب المستودع`: المستودع خاص ← ضع توكن GitHub في متغيّر `TOKEN` داخل الخلية، أو اعمل Fork عاماً.

### الخلية ٢ — تثبيت المكتبات
- ماذا تفعل: تنزّل `transformers`, `peft`, `trl`, `datasets`, `accelerate`, `bitsandbytes`.
- الزمن: ٣–٥ دقائق. سترى تحذيرات صفراء — **طبيعية، تجاهلها**.
- المتوقع في النهاية: `GPU: Tesla T4`.

### الخلية ٣ — البيانات والفحص
- ماذا تفعل: تقرأ كتالوج الأدوات من كود التطبيق، تولّد `train.jsonl`/`val.jsonl`، ثم تفحص الصيغة.
- المتوقع بالحرف:
  ```
  ✅ 236 أداة في 15 مجموعة → …/data/tools.json
  train=173 val=9
  182 مثالاً، 0 مشكلة
  ```
- إن ظهر غير ذلك: توقف وأرسل النص — لا تكمل التدريب على بيانات مكسورة.

### الخلية ٤ — تشغيل تجريبي (١٢ خطوة)
- ماذا تفعل: تتأكد أن التدريب يعمل فعلاً قبل الانتظار ساعة.
- الزمن: ٣–٥ دقائق.
- المتوقع: سطور `loss` تنخفض ثم `==== نتيجة التدريب ====`.
- **فائدة هذه الخلية:** إن كانت هناك مشكلة في إصدارات المكتبات تظهر الآن، لا بعد ساعة.

### الخلية ٥ — التدريب الكامل
- ماذا تفعل: تدرّب LoRA ٣ دورات على `Qwen2.5-1.5B-Instruct`.
- الزمن: **٤٥–٩٠ دقيقة**. لا تغلق التبويب.
- المتوقع: جدول خطوات فيه `loss` ينخفض تدريجياً من ~2.5 إلى ~0.8–1.5.
- تحذيران طبيعيان يمكن تجاهلهما: `use_cache=True is incompatible with gradient checkpointing` و`Some weights were not initialized`.
- **إن انقطع الاتصال:** أعد تشغيل الجلسة ونفّذ الخلايا ١→٢→٥ (البيانات سريعة) — أو استخدم خلية ٧ للحفظ على Drive قبل الانقطاع.

### الخلية ٦ — الدمج
- ماذا تفعل: تدمج محوّل LoRA داخل النموذج الأساسي لتنتج نموذجاً كاملاً.
- الزمن: ٢–٣ دقائق. المتوقع: `merged -> out/lion-1-merged`.

### الخلية ٧ — احتياط على Drive (اختياري لكن مُستحسن)
- ماذا تفعل: تحفظ `out/lion-1-lora` و`out/lion-1-merged` في `MyDrive/Lion-1`.
- إن ظهرت نافذة إذن Drive: **`Allow`**.

### الخلية ٨ — تحويل إلى GGUF كمّي
- ماذا تفعل: تجلب llama.cpp، تحوّل النموذج إلى GGUF، ثم تكمّمه إلى `Q4_K_M`.
- الزمن: ٥–١٥ دقيقة أول مرة (بناء أدوات llama.cpp).
- المتوقع في النهاية:
  ```
  ✅ جاهز: /content/LionAI/model/out/lion-1-Q4_K_M.gguf
     الحجم: 940 MB
     SHA-256: …
  ```
- **هذا هو الملف الوحيد الذي تحتاجه بعد كل هذا.**

### الخلية ٩ — التنزيل
- ماذا تفعل: تنزّل ملف GGUF إلى جهازك (نافذة تنزيل المتصفح).
- من الهاتف: قد يستغرق ١٠–٢٠ دقيقة على 940MB — استخدم Wi-Fi.

---

## ٥) أين ذهب «ملف LoRA»؟

داخل Colab في المسار `model/out/lion-1-lora` (بضع عشرات MB). **لا تحتاجه على الهاتف ولا ترفعه لأي مكان.**
وظيفته انتهت بعد الخلية ٦ (الدمج). أبقِه على Drive فقط إن أردت إعادة التكميم بمستوى آخر لاحقاً
(`Q5_K_M` مثلاً) بلا إعادة تدريب.

---

## ٦) انقل الملف إلى التطبيق (خطوة بخطوة)

### أ) ارفعه إلى HuggingFace (الأسهل من الهاتف)

1. أنشئ حساباً على **https://huggingface.co** (مجاني).
2. أعلى الصفحة: **`+`** ← **`New model`**.
3. الاسم: `lion-1` ← الخصوصية: **`Public`** ← **`Create model`**.
4. تبويب **`Files`** ← **`Add file`** ← **`Upload files`** ← اختر `lion-1-Q4_K_M.gguf` ← **`Commit changes`**.
   (940MB قد يحتاج دقائق؛ لا تغلق الصفحة.)
5. بعد الرفع اضغط على اسم الملف ← زر **`Copy download link`** أو **`Raw`**.
   الرابط سيكون بالشكل:
   ```
   https://huggingface.co/<اسمك>/lion-1/resolve/main/lion-1-Q4_K_M.gguf
   ```
   **انسخه** — هذا ما ستضعه في التطبيق.

> بديل بلا إنترنت: انسخ الملف إلى ذاكرة الهاتف، وفي التطبيق ضع **مسار الملف** بدل الرابط.

### ب) في التطبيق

1. افتح LionAI ← **☰** ← **🧰 أدوات المطوّر** ← **🖥️ البيئة المحلية**.
2. بطاقة **🦁 محرّك Lion-1** ← إن لم تكن البيئة مفعّلة: **⬇️ تحميل وتفعيل** وانتظر.
3. **📦 تثبيت المحرّك** (مرة واحدة فقط).
4. **＋ نموذج مخصص** ← الصق رابط HuggingFace ← **حفظ**.
5. **⬇️ تنزيل النموذج** (940MB — على الشاحن وWi-Fi، أبقِ التطبيق مفتوحاً).
6. **▶️ تشغيل** ← **🧪 اختبار** ← المتوقع: «✅ المحرّك يعمل» مع رد قصير.
7. اذهب للشات واختر المزود **🦁 Lion-1** وجرّب: «من أنت؟» ثم «اقرأ الملف …».

> إن غيّرت النموذج والمحرّك يعمل: التطبيق ينبّهك — اضغط **⏹️ إيقاف** ثم **▶️ تشغيل**.

## ٧) الأعطال الشائعة وحلولها

| المشكلة | السبب | الحل |
|---|---|---|
| لا يظهر `T4` في الشريط | لم يُفعَّل GPU | `Runtime → Change runtime type → T4 GPU → Save` |
| `تعذّر جلب المستودع` | مستودع خاص | توكن GitHub في `TOKEN` داخل الخلية ١، أو Fork عام |
| `pip` بطيء جداً أو ينقطع | شبكة | أعد تشغيل الخلية ٢ وحدها |
| الخلية ٣ تطبع غير `0 مشكلة` | بيانات مكسورة | لا تكمل؛ أعد تشغيل الخلية ٣ وأرسل النص |
| `CUDA out of memory` | النموذج 3B على T4 | استخدم `--base Qwen/Qwen2.5-1.5B-Instruct` (الافتراضي) |
| انقطع Colab بعد ساعة | حد الجلسة المجانية | الخلية ٧ (Drive) تحميك؛ أعد التشغيل من الخلية ١ ثم ٦→٨ (لا حاجة لإعادة التدريب إن حُفظ المدمج) |
| الخلية ٨ تفشل في `cmake` | بيئة Colab تغيّرت | نفّذ `!apt-get -qq install -y cmake build-essential` ثم أعد الخلية ٨ |
| النموذج على الهاتف بطيء جداً | 4GB رام | استخدم `Q4_K_M` (افتراضي) أو درّب `Qwen2.5-0.5B` |
| الملف لا ينزل من الخلية ٩ | حاجب نوافذ | من Drive: `MyDrive/Lion-1` ← انسخ GGUF إن حفظته، أو أعد الخلية ٨ |

## ٩) ماذا بعد؟

- **جودة أعلى:** وسّع البيانات إلى ٥٠٠+ مثال (`data/seed_extra.jsonl` أو `distill.py`) وأعد التدريب.

- المرجع التقني الكامل: `docs/LION1_TRAINING_AR.md` · المحرّك على الجهاز: `docs/LION1_ENGINE_AR.md`.
