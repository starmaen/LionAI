# تدريب Lion-1 (LoRA) — دليل عملي كامل

آخر تحديث: 2026-11-14 · الملفات: `model/` · دفتر Colab: `model/Lion1_LoRA_Colab.ipynb`

## ما الذي يتعلّمه النموذج فعلاً؟

| يتعلّم | لا يتعلّم |
|---|---|
| الهوية: «أسد / Lion-1 من Star Syria» | معرفة موسوعية (كتب/مقالات/تواريخ) |
| الأسلوب: عربية موجزة تبدأ بالجواب | حقائق متجددة (أسعار، إصدارات، أخبار) |
| صيغة أدوات التطبيق + أسماء الأدوات ومفاتيح وسائطها | «الإنترنت» — الأدوات هي التي تجلب، لا النموذج |
| متى لا يستدعي أداة، ومتى يسأل قبل عملية خطرة | — |

**القاعدة:** التدريب = **أسلوب ومهارة**. المعرفة = **أدوات واسترجاع**. من يحاول تدريب
نموذج 1.5B على موسوعة يحصل على نموذج يهلوس بثقة.

## المتطلبات

- حاسوب بكرت شاشة، **أو** Colab/Kaggle المجاني (**T4**). الهاتف لا يدرّب.
- بيانات: ٣٠٠–٢٠٠٠ مثال (١٨٠ الحالية تكفي للشكل فقط).
- الزمن: 45–90 دقيقة على T4 للنموذج 1.5B.

## المسار الكامل (خمس خطوات)

```bash
cd model
python data/import_tools.py        # 1) كتالوج الأدوات من AiTools.kt (236 أداة)
python data/generate_dataset.py    # 2) train.jsonl / val.jsonl
python eval_lion.py data data/train.jsonl data/val.jsonl   # 3) فحص الصيغة (بلا شبكة)
python train_lora.py --base Qwen/Qwen2.5-1.5B-Instruct --epochs 3   # 4) تدريب LoRA
python merge_export.py --base Qwen/Qwen2.5-1.5B-Instruct --lora out/lion-1-lora
python export_gguf.py --merged out/lion-1-merged --quant Q4_K_M     # 5) GGUF جاهز
```

أو افتح الدفتر جاهزاً: `model/Lion1_LoRA_Colab.ipynb` (كل الخلايا بالترتيب، وفيه خلية تنزيل الملف).

## ١) كتالوج الأدوات: لا تكتب أسماء الأدوات بيدك

`model/data/import_tools.py` يقرأ `app/src/main/java/com/lion/ai/AiTools.kt` ويولّد:

- `data/tools.json` — الأسماء فقط (للفحص في `eval_lion.py`).
- `data/tools_catalog.json` — الاسم + المجموعة + **وسائط نموذجية حقيقية** + الوصف + هل هي أداة كتابة.

ثم `generate_dataset.py` يبني من الكتالوج أمثلة «طلب مستخدم ← استدعاء أداة صحيح»، فلا يخترع
النموذج أسماء أدوات غير موجودة أو مفاتيح خاطئة (أشهر سبب لفشل الأدوات بعد التدريب).

للفحص في CI أو محلياً:

```bash
python model/data/import_tools.py --check   # يفشل إذا كان tools.json قديماً مقابل الكود
```

## ٢) البيانات: الصيغة والكم والجودة

كل سطر في `data/train.jsonl`:

```json
{"messages":[
  {"role":"system","content":"أنت «أسد» (Lion-1) …"},
  {"role":"user","content":"اقرأ الملف src/Main.kt"},
  {"role":"assistant","content":"[[TOOL]]{\"name\":\"file_read\",\"args\":{\"path\":\"src/Main.kt\",\"max_chars\":12000}}[[/TOOL]]"}
]}
```

قواعد تحريرية:

1. **استدعاء واحد في كل رد** (هكذا يتعامل معه `ToolAgent`)، وبلا نص خارج كتلة JSON.
2. بعد نتيجة الأداة يأتي رد `user` بصيغة `نتائج الأدوات:\n[اسم] …` ثم يجيب المساعد من النتيجة.
3. أمثلة **سلبية** ضرورية: أسئلة معرفية بلا أداة، وطلب تأكيد قبل عملية خطرة `[[ASK]]…[[/ASK]]`.
4. لا تُدرج أسماء مزوّدات/نماذج في الأجوبة (`eval_lion.py` يرفضها: تسريب).

### التوسيع

- يدوياً: أضف أسطراً إلى `data/seed_extra.jsonl` بنفس الصيغة.
- تلقائياً: `distill.py` يولّد من مزوّد قوي عبر بوابتك مع ترشيح صارم:

```bash
export LION_API_KEY=...        # RELAY_TOKEN لبوابتك
python distill.py prompts.txt --url https://<gateway>/v1 --model gemini/gemini-3.5-flash
python data/generate_dataset.py    # أعد التوليد لدمج seed_extra
```

راجع المخرجات يدوياً قبل التدريب، واحترم شروط استخدام المزوّد.

## ٣) التدريب

| معامل | القيمة المقترحة | لماذا |
|---|---|---|
| `--base` | `Qwen2.5-1.5B-Instruct` | التوازن لهاتف 4GB بعد Q4_K_M |
| `--epochs` | 3 (وإن ظهر overfit: 2) | ١٨٠ مثالاً × ٣ = ٥٤٠ خطوة تقريباً |
| `--lr` | 2e-4 | معتاد لـ LoRA |
| `--max_len` | 2048 | أمثلة الأدوات قصيرة؛ 4096 يهدر الذاكرة |
| `r=16, alpha=32` | افتراضي | كافٍ للهوية/الأسلوب |
| target modules | q,k,v,o + gate,up,down | يغطي الانتباه وMLP |

قبل التدريب الكامل شغّل **تجربة ١٢ خطوة** للتأكد أن كل شيء يعمل (تكشف تعارض إصدارات TRL):

```bash
python train_lora.py --dry_run
```

الناتج: `out/lion-1-lora` (محوّل LoRA وحده، عشرات MB) — وليس نموذجاً كاملاً.

## ٤) الدمج والتصدير GGUF

```bash
python merge_export.py --base Qwen/Qwen2.5-1.5B-Instruct --lora out/lion-1-lora
python export_gguf.py --merged out/lion-1-merged --quant Q4_K_M
```

`export_gguf.py` يجلب llama.cpp، يحوّل HF → f16 GGUF، ثم يكمّم إلى `Q4_K_M`، ويطبع الحجم
و SHA-256. خيارات التكميم: `Q4_K_M` (≈940MB، الافتراضي لهاتف 4GB) · `Q5_K_M` · `Q8_0` · `F16`.

## ٥) التشغيل داخل التطبيق

1. ارفع الملف إلى HuggingFace (مستودع عام) أو انسخه إلى الهاتف.
2. التطبيق ← **البيئة المحلية** ← **🦁 محرّك Lion-1** ← **＋ نموذج مخصص** ← الصق الرابط/المسار ← حفظ.
3. **⬇️ تنزيل النموذج** ← **▶️ تشغيل** ← **🧪 اختبار**.

الهوية Lion-1 تُحقن من التطبيق في كل طلب، فالتدريب يقوّي الأسلوب **فوق** تعليمات التطبيق لا بدلاً منها.

## التقييم (لا تنشر بلا أرقام)

```bash
# على حاسوبك: تشغيل النموذج المصدَّر
./serve.sh                       # llama-server على 8089
python eval_lion.py live --url http://127.0.0.1:8089/v1 --model lion-1
```

`eval_lion.py live` يفحص: الهوية، غياب تسريب أسماء النماذج، صحة كتل `[[TOOL]]` (JSON صالح،
أداة معروفة، وسيط واحد)، وسلوك الأسئلة المعرفية (بلا استدعاء أداة).

## أخطاء شائعة وحلولها

| العرض | السبب | الحل |
|---|---|---|
| `SFTConfig` يرفض معاملاً | تغيّر اسمه بين إصدارات TRL | النسخة الحالية تتكيّف تلقائياً (`max_length`/`max_seq_length`, `eval_strategy`/`evaluation_strategy`) |
| OOM على T4 مع 3B | 3B + 2048 يحتاج ذاكرة أكبر | استخدم 1.5B، أو `--batch 1 --grad_accum 16`، أو L4/A100 |
| النموذج «يحفظ» الأجوبة حرفياً | overfit (بيانات قليلة + دورات كثيرة) | أنقص `--epochs` إلى 2، وزد البيانات |
| يستدعي أدوات باسم مخترع | بيانات قديمة أو غير مستوردة | `python data/import_tools.py && python data/generate_dataset.py` |
| يجاوب بالإنجليزية | نقص أمثلة عربية | زد الأمثلة العربية في `seed_extra.jsonl` |
| GGUF يعمل على الحاسوب ولا يعمل على الهاتف | التكميم ثقيل للرام | استخدم `Q4_K_M` أو `Q4_0`، أو النموذج الأصغر 0.5B |
