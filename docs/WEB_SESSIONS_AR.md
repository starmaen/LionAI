# جلسات المواقع داخل الشات — نسخة اختبار جهاز

الأساس: bf0bc6344eb673c1daea82c5765c1f692c533de6
تاريخ التعديل: 2026-11-02

## الفرق عن الإصلاح السابق
هذا الإصدار يستبدل ربط أسماء مواقع الويب بموديلات Cloudflare. استدعاء مزود ويب في LlmClient ينتقل الآن إلى WebSessionTransport ثم WebView داخل MainActivity، ولا يستخدم عنوان WebGateway أو RELAY_TOKEN أو موديل API. مزودو API العاديون وخوادمهم لم يُلغوا.

## التشغيل
1. ثبّت APK كتحديث، دون حذف التطبيق أو بياناته. إذا رفض Android التحديث بسبب توقيع مختلف، لا تحذف النسخة الحالية؛ استخدم بناء GitHub بالتوقيع المعتاد.
2. الإعدادات ← Lion Chat ← فعّل جلسات المواقع ووافق على إرسال سياق الحوار إلى المواقع المختارة.
3. فعّل المواقع المطلوبة فرديًا أو «تفعيل الكل».
4. «الجلسة» تفتح WebView المملوكة لواجهة الشات. سجّل الدخول وأكمل أي تحقق يدويًا. الكوكيز تُدار داخل WebView، ولا تُنقل إلى خادم خارجي.
5. «فحص» يرسل رسالة حقيقية وينتظر جوابًا جديدًا مكتملًا. الفحص الجماعي يكرر ذلك بالتتابع؛ يمكن إلغاؤه. مهلة الموقع 90 ثانية في الفحص.
6. «للشات» يختار الموقع نفسه. «استخدام المجموعة في الشات» يجرب المفعّلين، لكن لا يعيد الإرسال لموقع آخر بعد وصول غير مؤكد للرسالة.
7. الصفحات الجانبية القديمة ما زالت متاحة. الأفضل تسجيل الدخول من «الجلسة» لأن بعض المواقع تستخدم تخزينًا خاصًا بالتبويب لا تشترك فيه الصفحات الأخرى.

## حدود مهمة
- يحتوي السجل على موصّلات DOM مبدئية لكل مواقع الدردشة الـ22 في PROVIDERS، وليس الوسائط المنفصلة.
- لم يتوفر هاتف المستخدم أو حساباته؛ لم تُثبت صلاحية محددات DOM على كل موقع حي. نجاح البناء واختبارات DOM المصطنعة ليس نجاحًا لاختبار المواقع الفعلية.
- بعض المحددات مبدئية/مشتركة وتحتاج ضبطًا حسب واجهة الموقع ولغته وإصداره. لا تُصنّف الصفحة ناجحة إلا بعد رجوع جواب مكتمل. العقل المركزي لا يرشح المواقع تلقائيًا إلا بعد فحص ناجح.
- إذا فشل موصّل: افتح «الجلسة»، ثم «تشخيص الصفحة» و«نسخ التشخيص». التقرير يجمع أسماء العناصر/خصائص CSS فقط؛ لا يجمع نص الرسائل أو قيم الحقول أو الكوكيز أو الروابط. قد تتضمن aria-label نصوصًا تعرضها واجهة الموقع، لذا راجعه قبل مشاركته.
- «محددات المطور» يسمح بتعديل حقل الإدخال، زر الإرسال، عنصر جواب المساعد، زر إيقاف التوليد، ومؤشر اكتمال/نسخ الرد دون إعادة بناء. لا تستخدم body أو حاوية المحادثة كلها لاستخراج الجواب.
- لا يتجاوز التطبيق CAPTCHA أو قيود الخدمة أو تسجيل الدخول. لا يضمن إمكانية التحكم الآلي بموقع لمجرد نجاح استخدامه يدويًا.
- النقل الآلي نصي حتى 60000 حرف من التعليمات والسجل والرسالة. الصور/الملفات الثنائية تحتاج رفعًا يدويًا من الصفحة. الملفات التي يحولها التطبيق إلى نص تدخل ضمن حد السياق.
- تعليمات الأدوات تمر كنص، والتنفيذ يبقى في ToolAgent وصلاحيات التطبيق؛ اتباع النموذج للبروتوكول غير مضمون. ليست function calling أصلية للموقع.
- يجب إبقاء واجهة التطبيق مفتوحة؛ ليس هذا خادم متصفح يعمل بلا واجهة في الخلفية.
- تحتفظ بعض المواقع بسياق سابق رغم الرجوع لمسار الدردشة الرئيسي؛ لا تدّعي هذه النسخة عزلاً كاملاً لمحادثات الموقع. عند الحاجة افتح محادثة جديدة داخل الجلسة قبل التبديل لسياق مستقل.

## الأمان والسلوك
- allowlist دقيق لأصل HTTPS لكل موقع، مع تحقق في Android وJavaScript.
- لا addJavascriptInterface ولا استخراج للكوكيز ولا إرسالها إلى Cloudflare.
- عدم استبدال مسودة موجودة في حقل الموقع.
- نقرة إرسال واحدة لكل معرّف طلب، وعدم إعادة الإرسال بعد فقدان سياقه.
- قبول جواب مساعد جديد فقط، وليس آخر جواب قديم أو نص الصفحة كله.
- اكتمال الرد يتطلب ثبات النص وإشارة توقف التوليد أو وجود مؤشر اكتمال/نسخ؛ ثبات النص وحده لا يكفي.
- الحفاظ على الأسوار البرمجية عند قراءة كتل الكود، وحذف نص أزرار التحكم من الجواب.
- طلب واحد يملك المتصفح في كل مرة، وإلغاء الطلب عند تدمير Activity، ومهلة انتظار محدودة.
- الاحتفاظ بثلاث WebViews كحد أقصى لتخفيف الذاكرة، مع بقاء كوكيز الدخول.
- التفعيل القديم للربط بالخادم لا يعد موافقة تلقائية على إرسال السجل إلى مواقع الويب؛ لذلك يلزم تفعيل جديد.

## نتائج التحقق
- testDebugUnitTest: نجح، 141 اختبارًا، صفر إخفاقات وأخطاء.
- npm --prefix scripts test: نجح، 13 اختبار DOM في jsdom.
- assembleRelease: نجح وأنتج APK موقّعًا. أول محاولات دمج DEX تجاوزت ذاكرة بيئة العمل (2GB)؛ نجح البناء بعد فصل التجميع والدمج وتحديد التوازي والذاكرة. هذه الخيارات محلية ولم تُفرض على GitHub.
- apksigner verify: تحقق من توقيع APK.
- git diff --check: نجح.
- لم يتم اختبار Android على جهاز/محاكي، ولم يتم اختبار جلسات المواقع الحية بحسابات المستخدم.
- لم تُرفع هذه التعديلات إلى GitHub من بيئة العمل. سكربت الرفع المرفق يستخدم تسجيل gh عند المستخدم ويدفع مباشرة إلى main دون force، ويتوقف عند تعارض patch.

## الملفات الرئيسية
WebSessionTransport.kt: وسيط الطلبات المتزامن مع عزل معرّفات الردود.
AndroidWebSessionHost.kt: دورة حياة WebViews، مهلة/إلغاء/التقاط الرد.
WebSessionPanel.kt: لوحة جلسة داخل Activity الشات.
WebSiteAdapters.kt: موصّلات المواقع ومحددات المطور.
assets/web-session.js: تحكم DOM دون صلاحيات أصلية.
LionChatSettingsCard.kt: تفعيل وفحص وتشخيص وإدارة الموصلات.
LlmClient.kt / WebChatRuntime.kt / RoutePolicy.kt: مسار الويب المستقل عن API.
