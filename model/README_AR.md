# Lion-1 — نموذج «الأسد» القابل للضبط

نموذج مفتوح (افتراضياً `Qwen2.5-1.5B-Instruct`) يُضبط بـ LoRA على هوية Lion-1 ومهامه المتعددة وعلى
**صيغة أدوات LionAI الحقيقية** (`[[TOOL]]{"name":…,"args":{…}}[[/TOOL]]` مع 234 اسم أداة من `data/tools.json`).

## الحالة الصادقة
- البيانات الحالية **عيّنة بذرية صغيرة (~75 مثالاً)**: تعلّم الهوية وصيغة الأدوات والأسلوب، ولا تُكسب النموذج معرفة جديدة.
- لم يُجرَّ تدريب فعلي بعد (يحتاج GPU). سكربتات البيانات والفحص اختُبرت؛ سكربت التدريب لم يُشغَّل.

## خط جاهز بأمر واحد (Colab)

`Lion1_LoRA_Colab.ipynb` ينفّذ المسار كاملاً: استيراد كتالوج الأدوات من كود التطبيق ← توليد
البيانات ← فحص الصيغة ← تجربة ١٢ خطوة ← تدريب ← دمج ← GGUF كمّي ← تنزيل الملف.
الدليل التفصيلي: `docs/LION1_TRAINING_AR.md` · ولأول مرة على Colab: `docs/LION1_COLAB_STEPBYSTEP_AR.md`
(لا ترفع أي ملف LoRA — الدفتر يصنعه؛ ترفع الدفتر فقط).

## الخطوات
0. `python data/import_tools.py` — يقرأ `AiTools.kt` ويولّد كتالوج الأدوات وأمثلتها (236 أداة).
   لا تكتب أسماء الأدوات بيدك: الخطأ هنا يجعل النموذج يستدعي أدوات غير موجودة.
1. **وسّع البيانات**: أضف أمثلة إلى `data/seed_extra.jsonl`، أو ولّدها من مزودات قوية عبر بوابتك:
   `LION_API_KEY=… python distill.py --url <gateway>/v1 --model <provider/model> prompts.txt`
2. `python data/generate_dataset.py` ثم `python eval_lion.py data data/train.jsonl data/val.jsonl`
3. **درّب** على Colab/Kaggle (T4 مجانية): `pip install -r requirements.txt && python train_lora.py`
4. `python merge_export.py` ثم حوّل إلى GGUF (الأوامر في أعلى الملف) وشغّل `./serve.sh` أو `ollama create lion-1 -f Modelfile`
5. **اختبر**: `python eval_lion.py live --url http://127.0.0.1:8089/v1 --model lion-1`
6. أضفه في التطبيق مزوداً مخصصاً (OpenAI-Compatible): `http://127.0.0.1:8089/v1` والموديل `lion-1`.

## تشغيل نموذجك داخل التطبيق مباشرة (محرّك Lion-1 المدمج)

بدل تشغيل خادم خارجي، التطبيق يستطيع تشغيل النموذج بنفسه: `LionEngine` يثبّت `llama-server`
داخل Alpine ويشغّله على `127.0.0.1:44045` بنموذج GGUF. بعد تصدير GGUF من خطوتك (4):

1. ارفع الملف إلى HuggingFace أو ضعه على الجهاز.
2. التطبيق ← البيئة المحلية ← بطاقة **🦁 محرّك Lion-1** ← «＋ نموذج مخصص» ← ضع الرابط/المسار ← حفظ.
3. «⬇️ تنزيل النموذج» ثم «▶️ تشغيل» ثم «🧪 اختبار».

الهوية Lion-1 تُحقن من التطبيق فوق النموذج، فالتدريب يقوّي الأسلوب وصيغة الأدوات بدل أن يكرّرها.
التفاصيل الكاملة: `docs/LION1_ENGINE_AR.md`.

## `integration/`
`LionModel.kt` (توجيه المهام وتبديل الخادم داخل التطبيق) و`lion-model.js` (نموذج افتراضي على البوابة) —
بديل خفيف يعمل فوق أي نموذج دون تدريب.

## تحسين الجودة والنشر على Hugging Face (Colab)

**لماذا كان النموذج ضعيفاً؟** البيانات الأساسية ~١٧٠ مثالاً مولَّدة بقوالب: تكفي لتعلّم الهوية وصيغة `[[TOOL]]` لا لجودة عامة.
ما يحسّن الجودة فعلاً بترتيب الأثر:

1. **توسيع البيانات** — خلية ٣-ب في الدفتر تشغّل `distill_local.py`: نموذج معلّم مفتوح أكبر (Qwen2.5-7B، 4-bit على T4)
   يولّد مئات الأمثلة العربية المتنوعة، وتُرشَّح تلقائياً (تسريب أسماء، كتل أدوات، ردود مقطوعة/مكرّرة، لغة).
   لا يحتاج مفتاح API. **راجع العيّنة بعينك** قبل التدريب.
2. **حفظ أفضل نقطة** — `train_lora.py` يختار الآن أفضل دورة بحسب `eval_loss` بدل آخر دورة.
3. **بوابة جودة** — خلية ٦-ب (`eval_merged.py`) تختبر الهوية وعدم التسريب واختيار الأدوات قبل أي نشر.
4. **النشر** — خلية ٨-ب (`publish_hf.py`) ترفع GGUF وبطاقة النموذج إلى مستودعك على Hugging Face.

### توكن Hugging Face
أنشئ توكناً بصلاحية **Write** من https://huggingface.co/settings/tokens، ثم في Colab: أيقونة 🔑 ← Add new secret ←
الاسم `HF_TOKEN` ← فعّل Notebook access. لا تلصقه في الكود ولا في الدردشة.

### السرعة على الهاتف
السرعة تحدّدها حجم النموذج والسياق لا التدريب: **Nano (0.5B)** الأسرع، **Mini (1.5B)** المتوازن، **Base (3B)** الأبطأ
وأدق. على هاتف 4GB أبقِ Mini/Nano وسياق 4096. قِس على جهازك قبل الحكم.

### ترخيص النموذج الأساس
Qwen2.5-0.5B/1.5B/7B بترخيص Apache-2.0، أما **Qwen2.5-3B فبترخيص Qwen Research** (غير تجاري) — `publish_hf.py` يضبط
حقل الترخيص في البطاقة حسب القاعدة، لكن تحقّق من صفحة النموذج الأساس قبل النشر العام.
